Capturekit: Product Requirements Document

Version: 1.0 | Date: 2026-09-29 | Status: Draft for build Working title: Capturekit (autonomous visual capture for shipped software)

1. Executive Summary

Capturekit is a CLI-first, CI-native tool that turns any running web project (localhost, preview deploy, or production URL) into a complete, current visual asset pack: multi-viewport screenshots, walkthrough videos, GIFs, and a shareable gallery, with no manual steps after initial setup.

The product thesis: visual material is needed on every release but is skipped because it is tedious. Capturekit removes the tedium by making capture autonomous: it discovers pages, stabilizes them, handles overlays and animations, captures in parallel across devices, retries on flakiness, and publishes a gallery, all triggered by a single command or a git event.

Core promise: capturekit run on any URL yields a client-ready gallery in under 2 minutes, with zero per-page scripting for the common case.

3. Goals and Non-Goals

Goals

  • G1 Autonomy: Zero-config first run; config only to refine.
  • G2 Fidelity: Captures look production-grade (retina, real device profiles, stable frames).
  • G3 Speed: All viewports in parallel; total time close to the slowest single capture.
  • G4 Determinism: Same input yields visually consistent output across runs.
  • G5 Shareability: Output is one link or one folder a client can open.
  • G6 Integration: Runs identically locally and in CI.

Non-Goals (v1)

  • Visual regression diffing and baselines (Percy/Chromatic territory).
  • Native mobile app capture.
  • A hosted SaaS, accounts, or billing.
  • A visual editor or annotation UI.
  • Cross-browser matrix beyond Chromium (WebKit/Firefox are v1.x).

4. Personas

  1. Freelance engineer (primary): Needs portfolio and client update visuals fast. Values: speed, polish, zero babysitting.
  2. Agency lead: Sends weekly progress to multiple clients. Values: consistent branding, one shareable link, history.
  3. Reviewer / PM: Wants previews inside PRs. Values: no setup, visible in the PR thread.
  4. Bug reporter: Wants a short clip of a flow. Values: one command, small file.

5. Product Principles

  1. Autonomous by default, controllable by exception. Smart defaults do the work; config overrides them.
  2. Never fail silently, never fail wholly. One broken page must not sink the run; every failure is reported with a reason and a retained trace.
  3. Boring core, sharp edges only where valuable. Playwright does capture; we own orchestration, stabilization, and packaging.
  4. Outputs are artifacts, not logs. Every run produces a versioned, self-describing folder.
  5. Local-first. No data leaves the machine unless the user publishes.

6. Functional Requirements

Priority: P0 = MVP, P1 = client-ready release, P2 = later.

6.1 Discovery (the autonomy engine)

ID Requirement Pri
FR-1 Accept a single URL and auto-discover pages via sitemap.xml, then robots hints, then same-origin link crawl (depth and count limits configurable, default depth 2, max 20 pages) P0
FR-2 Route-source adapters: read routes from Next.js/Nuxt/SvelteKit/Astro/React Router build manifests or file-system routing when a project path is supplied P1
FR-3 Deduplicate parameterized routes (/post/1, /post/2) by URL pattern; capture one representative P0
FR-4 Page ranking: prioritize home, top-nav destinations, and pages by inbound link count when the cap is hit P1
FR-5 Explicit include/exclude globs override discovery P0

6.2 Capture

ID Requirement Pri
FR-6 Built-in device profiles: mobile (iPhone), tablet (iPad), laptop, desktop; custom width/height/DPR supported P0
FR-7 One browser, one isolated context per viewport, executed concurrently with a bounded worker pool (default: min(cores, 4)) P0
FR-8 Screenshot modes: viewport, full-page, element (by selector), and "above-the-fold" P0
FR-9 Formats: PNG, WebP, JPEG (quality configurable); optional device-frame mockups (browser chrome / phone bezel) P1
FR-10 Dark/light scheme capture via prefers-color-scheme; optional reduced-motion P1
FR-11 Per-page and per-viewport overrides in config P0

6.3 Stabilization (what makes it trustworthy)

ID Requirement Pri
FR-12 Ready detection: wait for network idle, fonts loaded (document.fonts.ready), images decoded, and DOM mutation quiescence (no mutations for N ms) P0
FR-13 Lazy-content trigger: auto-scroll to bottom and back to fire intersection observers before full-page capture P0
FR-14 Animation control: inject CSS to disable transitions/animations and pause videos/carousels; optional "settle" mode that waits instead P0
FR-15 Overlay handling: auto-dismiss cookie banners, chat widgets, and newsletter modals via a maintained selector/heuristic library; user-extensible P1
FR-16 Determinism controls: freeze time (page.clock), seed Math.random, mask/blur dynamic regions by selector P1
FR-17 Self-healing retry: on timeout, blank frame, or layout shift above threshold, retry with escalated waiting strategy (up to 3 attempts), then record failure with trace P0
FR-18 Blank/broken frame detector: reject captures that are near-uniform, error pages (HTTP 4xx/5xx, framework error overlays), or contain console-error banners P1

6.4 Video and Motion

ID Requirement Pri
FR-19 Record one video per viewport with size matched to the viewport P0
FR-20 Auto-generated scroll-through walkthrough for every page (smooth, eased, configurable speed) P0
FR-21 Scripted flows in config: click, fill, hover, press, waitFor, scroll, goto; optional visible cursor and click ripple overlay P1
FR-22 Post-process with ffmpeg: MP4 (H.264), GIF, WebM; trim dead time; compress to size budget (default under 5 MB per clip) P0
FR-23 Optional captions and title cards from flow step names P2
FR-24 Contexts closed before file finalization (correctness requirement) P0

6.5 Auth and Environment

ID Requirement Pri
FR-25 Login recipe (fill + submit + wait) that saves Playwright storageState, reused across viewports P1
FR-26 Secrets read from env vars; never written to output or logs P0
FR-27 Optional start command: boot the app, wait for a health URL, capture, tear down (makes CI trivial) P1
FR-28 Custom headers, cookies, geolocation, locale, timezone P1

6.6 Packaging and Output

ID Requirement Pri
FR-29 Deterministic output tree per run (see Section 9) with manifest.json describing every asset P0
FR-30 Generated static gallery (index.html): responsive grid, viewport tabs, lightbox, video playback, copy-link buttons; zero external dependencies P0
FR-31 Theming: logo, colors, title, client name, footer for white-label client delivery P1
FR-32 Export: ZIP of assets, single PDF summary, Markdown snippet for READMEs and PR comments P1
FR-33 Run history and "latest" symlink; before/after slider between two runs P2
FR-34 Publish adapters: local folder, S3/R2, GitHub Pages, Netlify/Vercel drop P2

6.7 Triggers and Automation

ID Requirement Pri
FR-35 CLI: init, run, discover, doctor, open, clean P0
FR-36 Watch mode: recapture affected pages on file change (debounced) P2
FR-37 Official GitHub Action: boots app or targets preview URL, uploads artifact, posts/updates a single PR comment with thumbnails P1
FR-38 Webhook trigger endpoint mode for deploy hooks (Vercel, Netlify) P2
FR-39 Exit codes and JSON output for scripting P0

6.8 AI-Assisted Layer (optional, off by default)

ID Requirement Pri
FR-40 Flow synthesis: given a URL and a plain-English goal ("show signup and dashboard"), an LLM agent explores and emits a reviewable flow config P2
FR-41 Alt text and captions: vision model generates alt text and one-line descriptions per screenshot P2
FR-42 Visual QA pass: flag clipped text, overlapping elements, and horizontal overflow before delivery P2
FR-43 Client summary: generate a short "what changed" blurb from git diff and screenshots P2

AI features never run silently: they emit files the user can review, and the tool functions fully without them.

7. Non-Functional Requirements

Category Requirement
Performance 5 pages x 3 viewports (15 screenshots) in under 45 s on a 4-core laptop; adding walkthrough videos under 2 min total
Reliability 99% capture success on a benchmark corpus of 50 public sites; failed captures never abort a run
Determinism Two runs on unchanged content differ by less than 0.5% pixels after masking
Resource use Peak memory under 1.5 GB at default concurrency; auto-throttle on low memory
Portability macOS, Linux, Windows; Node 20+; Docker image for CI
Security Local-only by default; secrets redaction; no telemetry without opt-in; SSRF guard when run as a service
Accessibility Gallery meets WCAG 2.1 AA (keyboard nav, alt text, contrast)
Observability Structured logs, per-capture timing, Playwright trace retained on failure
Install npx capturekit works with no global install; browsers auto-provisioned by doctor

8. System Architecture

flowchart LR
  A[CLI / GitHub Action] --> B[Config Loader<br/>+ Zod validation]
  B --> C[Discovery Engine]
  C --> D[Job Planner<br/>page x viewport x mode]
  D --> E[Worker Pool<br/>p-limit]
  E --> F[Browser Contexts<br/>Playwright]
  F --> G[Stabilizer<br/>ready, scroll, freeze, overlays]
  G --> H[Capture<br/>screenshot / video]
  H --> I{Validator<br/>blank? error? shift?}
  I -- fail --> J[Retry Ladder]
  J --> G
  I -- pass --> K[Post-Processor<br/>ffmpeg, sharp]
  K --> L[Packager<br/>manifest + gallery]
  L --> M[Publishers<br/>folder, PR comment, S3]

Key design decisions

  • Language/stack: TypeScript, Node 20, Playwright, sharp (images), ffmpeg-static (video), Zod (config), commander (CLI), p-limit (concurrency).
  • Job model: each capture is an idempotent job (page, viewport, scheme, mode) with its own retry state, enabling parallelism and partial reruns.
  • Retry ladder: attempt 1 = standard waits; attempt 2 = longer settle + animation kill + scroll warm-up; attempt 3 = reload with cache cleared + domcontentloaded fallback. Each rung is logged.
  • Plugin surface (P2): discoverer, stabilizer, publisher, and postprocessor hooks so extensions never touch the core.

10. Configuration Schema (capture.config.ts)

export default defineConfig({
  target: "http://localhost:3000",
  start: { command: "npm run dev", waitOn: "http://localhost:3000/health" },
  discovery: { mode: "auto", depth: 2, maxPages: 12, exclude: ["/admin/**"] },
  viewports: ["mobile", "tablet", "desktop"],          // or custom objects
  schemes: ["light"],                                    // add "dark"
  capture: { fullPage: true, format: "webp", frame: "browser" },
  stabilize: { networkIdle: true, freezeTime: "2026-01-01T00:00:00Z",
               dismissOverlays: true, mask: [".timestamp", "[data-ad]"] },
  video: { walkthrough: true, formats: ["mp4", "gif"], maxSizeMB: 5 },
  flows: [{
    name: "Checkout",
    steps: [
      { goto: "/products" },
      { click: "text=Add to cart" },
      { click: "[data-testid=checkout]" },
      { waitFor: "text=Order summary" }
    ]
  }],
  auth: { recipe: "./auth.ts", storageState: ".auth/state.json" },
  gallery: { title: "Acme Redesign", client: "Acme Inc.", brand: { logo: "./logo.svg", accent: "#0F62FE" } },
  publish: [{ type: "github-pr-comment" }]
});

Zero-config equivalent: npx capturekit run http://localhost:3000.

11. User Flows

  1. First run (30 seconds): npx capturekit run <url> → discovery finds pages → captures 3 viewports → opens gallery. No config file.
  2. Client delivery: capturekit init (brand, viewports) → capturekit run --publish s3 → link pasted into email.
  3. PR preview: push → Action boots app → captures changed routes → PR comment with thumbnails and gallery artifact.
  4. Bug clip: capturekit run --flow ./repro.yml --video --format gif → small GIF ready to attach.

13. Risks and Mitigations

Risk Likelihood Impact Mitigation
Flaky captures erode trust High High Ready-detection stack, retry ladder, validator, failure traces
Cookie/overlay variety is endless High Medium Heuristic library + user-extensible selectors + "manual mask" fallback
Auth flows differ per site Medium Medium Recipe scripts + storageState, documented patterns
Video size/encoding pain Medium Medium ffmpeg presets with a size budget and two-pass encoding
Scope creep (diffing, dashboard, SaaS) High High Non-goals enforced; only P0/P1 until CLI is dogfooded
Crawl abuse / hitting production hard Low High Rate limiting, robots respect, default page cap, concurrency cap
Sensitive data in screenshots Medium High Mask selectors, --redact mode, warn on detected emails/tokens (P1)

15. Acceptance Criteria (MVP)

  • npx capturekit run <url> completes with no config and produces a working gallery.
  • Three viewports execute concurrently; wall time is under 1.5x the slowest single capture.
  • A page with lazy images, a cookie banner, and a CSS animation produces a clean full-page screenshot.
  • A forced timeout triggers the retry ladder and is recorded in the manifest.
  • A permanently broken page is reported as failed while all other pages still succeed.
  • Every video is finalized (context closed) and compressed under the size budget.
  • No secrets appear in logs or output.
  • Exit code is non-zero only when configured failure thresholds are exceeded.

16. Testing Strategy

  • Unit: discovery parsing, config validation, URL dedupe, retry logic.
  • Integration: fixture sites (static, SPA, lazy-load, cookie banner, auth wall, infinite scroll) served locally.
  • Benchmark corpus: 50 public sites, run nightly, tracking success rate and duration.
  • Determinism test: run twice, assert pixel difference under threshold.
  • Cross-platform CI: matrix on macOS, Linux, Windows.

18. Appendix: Why This Stays Simple

The heavy lifting (rendering, recording, device emulation) is delegated to Playwright and ffmpeg. Capturekit's own code is orchestration: discover, plan, capture, validate, package. Autonomy comes from four small, well-tested mechanisms (ready detection, the retry ladder, the validator, and heuristic overlay handling) rather than from a large codebase. That is what keeps the MVP at a weekend while the finished product feels like it does the work for you.
